# Working together

Start the demo and inspect one recorded case before editing. Choose context enrichment, local discovery or integration/evaluation as your work area. Agree ownership of shared files with the team so both tracks can progress without incompatible interfaces.

Use a short feature branch and a pull request describing the user-visible result, changed contract fields, tests and remaining limits. Preserve the main branch as a working demo. No branch protection has been configured by this preparation.

Run `npm run check` before sharing a change. For routes, review controls or versioning, also run `npm run test:e2e`. Keep the `.env` file, `.local/`, API keys and browser artifacts untracked. Reuse `shared/research.ts` rather than creating a separate incompatible result format.

The team should agree its city/stay, test identity sources, source provider and budget before real research. Document the decision in the relevant track brief. A successful empty result is preferable to invented evidence. Never label a simulation or a cached source as a live availability check.

The repository is private and no public license has been selected. Ask the owner before redistribution or publication. Follow the event's rules for declaring inherited code; this project already includes a substantial pre-event Canopia core and preparation workflow.
